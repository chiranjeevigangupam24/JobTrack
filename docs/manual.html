1. Executive Project Summary & Real-World Problem Statement

Finding employment in the modern software industry requires managing high volumes of applications across diverse job portals (LinkedIn, Naukri, Indeed, AngelList, and direct career sites). Typical applicants submit dozens of applications, navigate multi-stage interviews, complete timed coding assessments, and negotiate multiple offers.

Job seekers frequently encounter critical organizational bottlenecks:

  • Missed Milestones: Forgetting take-home coding deadlines or timely recruiter follow-ups.
  • Scattered Schedules: Misplacing interview calendar invites and meeting URLs minutes before calls.
  • Lack of Funnel Visibility: Inability to see where applications drop off (e.g. resume screening vs. technical rounds).
  • Data Vulnerability: Typical spreadsheets easily corrupt, lack atomic write safety, and present security risks when exporting.

JobTrack Pro provides an offline-first, highly disciplined platform. It offers a modern React 18 & Tailwind CSS web dashboard, a high-speed FastAPI backend, an automated deadline reminder engine, and a resilient atomic JSON storage layer.

5. Storage & Persistence Engine (`src/storage`)

The persistence layer in json_storage.py implements enterprise-level file writing safety guarantees without requiring external SQL/NoSQL services.

The Flaw in Standard File I/O
Writing directly with open("applications.json", "w") truncates the file immediately. A crash or power drop mid-write leaves a 0-byte corrupt file, causing complete data loss.

JobTrack Pro's Atomic 5-Step Write Sequence:

  1. In-Memory Serialization: Serializes records into a validated JSON string.
  2. Temporary File Creation: Writes data to a process-isolated temporary file: applications.json.tmp.<PID>.
  3. Buffer Flush: Calls f.flush() to clear application-level write buffers.
  4. Physical Disk Sync: Executes os.fsync(f.fileno()), forcing the OS kernel to commit bits to physical SSD/HDD storage.
  5. Atomic Rename: Calls os.replace(temp_file, final_file). In POSIX and Windows NT, os.replace is atomic. Either the new file replaces the target completely, or the previous file remains untouched.

6. Business Logic & Service Layer (`src/services`)

ApplicationService

Manages CRUD lifecycle. Features a tokenized multi-field search matching across company, role, applicant name, and notes. Supports multi-field filtering by status, job type, and location.

InterviewService

Schedules interview rounds, validates chronological ordering, records pass/fail outcomes, and automatically advances applied jobs to INTERVIEWING.

ReminderService

Calculates milestone urgency: (1) Today's Interviews, (2) Upcoming schedules within lookahead window, (3) Expiring or overdue assessment deadlines. Filters out inactive applications.

AnalyticsService

Aggregates stage distributions, computes Interview Rate %, Offer Rate %, and Interview-to-Offer conversion percentage.

7. Defensive Programming & Security

CSV Formula Injection Defense (CSV Command Injection / DDE)

When CSV files are opened in Microsoft Excel or Google Sheets, cells starting with formula trigger symbols (=, +, -, @) are executed as spreadsheet formulas or system commands.

In src/reports/csv_exporter.py, every cell is sanitized before writing:

def sanitize_cell(value: str) -> str:
    if isinstance(value, str) and value.startswith(("=", "+", "-", "@", "\t", "\r")):
        return f"'{value}"  # Prepends single quote to force literal text treatment
    return value

8. FastAPI REST Backend (`server.py`)

The backend wraps domain services in asynchronous HTTP endpoints with Pydantic v2 schemas:

  • GET /api/dashboard: High-efficiency aggregated payload delivering stats, urgent alerts, and recent applications in one network call.

  • GET /api/export/{export_type}: Safe CSV report streaming.

12. Technical Viva Voce & Interview Defense Q&A

Q1: Why choose a Layered Architecture instead of writing code directly in FastAPI endpoints?
Separating the codebase into Models, Services, and Storage prevents business logic from being tightly coupled to HTTP protocols. The exact same business logic simultaneously powers both the Web API and the Terminal CLI without code duplication. It also enables isolated unit testing without running a network server.
Q2: How does the Atomic Write mechanism prevent file corruption?
Directly writing to a file truncates it immediately; if interrupted, data is lost. Our JSONStorage writes to a temporary file (.tmp), flushes internal buffers, forces a disk write with os.fsync(), and renames it atomically via os.replace(). In operating systems, os.replace() guarantees atomic replacement: the update either completely succeeds or leaves the original file unchanged.
Q3: What is CSV Formula Injection and how is it mitigated?
Spreadsheets automatically execute cell values beginning with =, +, -, or @ as formulas or commands. We neutralize this in CSVExporter by prepending a single quote (') to any string starting with formula characters, instructing the spreadsheet to treat the content as literal text.
Q4: Why use CDN-delivered React 18 instead of a traditional Webpack/Vite build?
To maintain zero-dependency simplicity and instant portability. Evaluators, students, and recruiters can run the full web application immediately using standard Python, eliminating node_modules bloat, version mismatches, and build setup errors.
